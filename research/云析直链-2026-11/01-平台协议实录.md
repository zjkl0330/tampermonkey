# 网盘直链 · 平台协议实录

> 记录时间：2026-11-09 ~ 2026-11-10
> 环境：Chromium 124 / Tampermonkey、Ubuntu 22.04 沙箱、curl、Playwright
> 说明：所有结论都来自实际请求，不是文档推测。错误码为服务端原文。

---

## 0. 通用结论（先看这段）

| 结论 | 说明 |
| --- | --- |
| 纯前端拿不到「免登录直链」 | 除夸克 / UC 外，其余平台的下载接口都要求登录态。第三方解析站能免登录，是因为它们有自己的账号池跑在服务端 |
| `HttpOnly` Cookie 读不到 | `BDUSS`（百度）、`sessionKey`（天翼）都是 HttpOnly，`document.cookie` 和 `GM_cookie` 都拿不到，**不能用 Cookie 判断登录态** |
| 同一站点内用 `fetch` 比 `GM_xmlhttpRequest` 更稳 | Cookie 自动带、不需要任何 GM 权限，手机浏览器也能跑 |
| 跨站必须用 `GM_xmlhttpRequest` | 自定义 `User-Agent` / `Referer` 在 `fetch` 里会被浏览器丢弃 |
| 老接口的参数可能是「化石」 | 百度 `locatedownload` 的 `psign` / `devuid` 是写死的历史值，接口还在但校验早变了 —— 表现为「登录了也拿不到链」 |

## 1. 夸克网盘

```
POST https://drive-pc.quark.cn/1/clouddrive/share/sharepage/token
     { "pwd_id": "<id>", "passcode": "<pwd>" }        → stoken
GET  .../share/sharepage/detail?pwd_id=&stoken=&pdir_fid=0&_page=1&_size=50
                                                       → 文件列表 + share_id
POST .../file/download                              → download_url
```

- **注意路径**：是 `file/download`，不是 `sharepage/file/download`，写错直接 404。
- 游客链必须带 `__pugs` Cookie，否则 CDN 返回 **412**。
- 分享是文件夹时要递归，`pdir_fid` 逐层传。
- 未登录单文件约 **50MB** 上限，超了返回 `23018`。
- UA 必须是 PC 客户端：`quark-cloud-drive/2.5.20 ... Channel/pckk_other_ch`。

## 2. UC 网盘

与夸克同一套 clouddrive 协议，只换域名与 UA：

| 项 | 值 |
| --- | --- |
| 域名 | `drive.uc.cn` / `pc-api.uc.cn` |
| UA | `UCBrowser ... Channel/pckk_other_ch` |
| 路径 | 同夸克 |

实测取链后 CDN 返回 200，`Content-Length` 与列表里的 size 一致。

## 3. 123 云盘

```
GET https://www.123865.com/a/api/share/get?shareKey=&S3=0&...
     → 匿名可读列表
```

- 签名：`SIGN_TABLE` 固定表 + 文件 `crc32`，按 key 排序拼接后取 md5。
- **匿名下载统一返回 `5112 您需要注册登录或付费后下载`**，这一条是硬门槛。
- 登录后 token 在 `localStorage.authorToken`。

## 4. 115 网盘

```
GET https://webapi.115.com/share/snap?share_code=&receive_code=&offset=0&limit=20&asc=0&cid=0&format=json
     → 游客可用，返回目录树
GET https://webapi.115.com/share/downurl?file_id=
     → 游客返回 {"state":false,"errno":990001,"msg":"登录超时"}
```

- 取链接口认客户端 UA：`115Browser/25.0.2.5`。
- 游客只能列目录。

## 5. 天翼云盘

```
GET https://cloud.189.cn/api/open/share/getShareInfoByCodeV2?shareCode=
     → shareId
GET .../listShareDir?shareId=&fileId=&sessionKey=
GET .../getFileDownloadUrl?fileId=&sessionKey=
```

- `sessionKey=null` 时返回 `InvalidSessionKey`。
- 登录后同源请求自动带 Cookie 即可。

## 6. 移动云盘（139）

这条是最麻烦的，请求体整段加密。

```
POST https://share-kd-njs.yun.139.com/yun-share/richlifeApp/devapp/IOutLink/getOutLinkInfoV6
body = base64( IV(16字节) + AES-CBC(JSON, key="PVGDwmcvfs1uV3d1") )
```

必备请求头：

```
hcy-cool-flag: 1
x-deviceinfo: <设备信息>
x-huawei-channelsrc: 10000003
x-mm-source: share
```

坑位：

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 根目录 ID | 传 `""` 或 `"0"` 都不对 | 必须 `pCaID: "root"` |
| 分页大小 | `eNum=300` 报「远程服务器操作失败」 | 上限 **200** |
| 响应压缩 | JSON.parse 直接失败 | 前两字节 `1f 8b` 就用 `DecompressionStream('gzip')` 再解一次 |
| linkID 位置 | 解析不到分享 ID | 在 URL 的 **hash** 里，不能 `split('#')[0]` |

取链 `dlFromOutLinkV3` 返回 `200000401 IP 鉴权失败 / 用户账号鉴权失败`。

## 7. 阿里云盘

POST https://api.aliyundrive.com/adrive/v3/share_link/get_share_by_anonymous
     { "share_id": "..." }                            → 匿名可列
POST https://api.aliyundrive.com/v2/share_link/get_share_token

     header: x-share-token

## 8. 百度网盘

### 8.1 游客态：官方已关闭

```
GET /rest/2.0/xpan/share?method=list&shorturl=...  → {"errno": -6}
```

`errno=-6` 就是「未登录」。2023 年后百度不再给游客取链，纯前端绕不过。

### 8.2 登录后 · 路线 A：免转存（推荐）

```
GET  /share/tplconfig?fields=sign,timestamp&surl=1xxxx&bdstoken=&logid=
     → data.sign / data.timestamp
POST /api/sharedownload?sign=&timestamp=&bdstoken=&logid=&jsToken=
     body: encrypt=0&product=share&uk=&primaryid=&fid_list=[fsid]&extra={"sekey":""}
     → list[0].dlink
```

参数来源全在**页面上下文**里，不需要额外请求：

| 参数 | 来源 |
| --- | --- |
| `bdstoken` | `window.locals.dump().bdstoken.value` |
| `jsToken` | `window.jsToken` |
| `sekey` | `window.currentSekey` 或 `window.cache.list.config.params.sekey` |
| `share_uk` / `shareid` | `window.locals.dump()` |
| `logid` | `btoa(BAIDUID)` |

`bdstoken` 读不到时兜底：同域 `GET /api/gettemplatevariable?fields=["bdstoken"]`，Cookie 由浏览器自动带。

### 8.3 登录后 · 路线 B：转存兜底

```
POST /api/create?a=commit   path=/yunx&isdir=1     → 建临时目录
POST /share/transfer?shareid=&from=uk&sekey=       → extra.list[0].to_fs_id
GET  /api/filemetas?dlink=1&fsids=[id]&bdstoken=   → info[0].dlink
```

**为什么换掉 `locatedownload`**：原来的 `d.pcs.baidu.com/rest/2.0/pcs/file?method=locatedownload` 带的是写死的 `psign=860a071f...`、`devuid=0F1E9FC2...`，这些是历史版本客户端的固定值，服务端早已不认。表现为「转存成功了，但取链报错」。`api/filemetas` 是网页版真实在用的接口。

### 8.4 错误码

| errno | 含义 |
| --- | --- |
| `-6` | 未登录 |
| `2` | 参数错误（多为 Cookie 不完整，或子目录缺 `BDCLND`） |
| `-9` / `12` | 提取码不正确 |
| `9019` | need verify（签名/令牌过期） |
| `112` | 页面过期 |
| `105` | 链接不存在 |

子目录两个坑：

1. `root` 根目录传 `1`，子目录传 `0`，传错进不去；
2. 子目录必须带 `BDCLND` Cookie（= 提取码换来的 `randsk`），否则 `errno=2`。

## 9. 迅雷云盘

### 9.1 captcha 签名（9 层 md5）

```js
sign = "1." + md5×9( client_id + "1.93.10" + "pan.xunlei.com" + device_id + timestamp + salt[i] )
```

```
POST https://xluser-ssl.xunlei.com/v1/shield/captcha/init
     { client_id, action, device_id, meta: { captcha_sign, timestamp, ... } }
     → captcha_token（约 300s）
```

`action` 要与后续请求匹配，例如 `GET:/drive/v1/share`、`GET:/drive/v1/share/detail`。

### 9.2 匿名可列目录（2026-11 实测）

```
GET https://api-pan.xunlei.com/drive/v1/share?share_id=&pass_code=&limit=100
GET https://api-pan.xunlei.com/drive/v1/share/detail?share_id=&parent_id=&pass_code_token=
headers: X-Client-Id / X-Captcha-Token / X-Device-Id
```

实测结果（`pan.xunlei.com/s/VOn6f4Fs...?pwd=jzv5`）：

| 项 | 结果 |
| --- | --- |
| captcha_token 长度 | 743 字符 |
| 根目录 | `share_status: OK`，`title` 正确 |
| 子目录 | 逐层正常（根 → 8 项 → 子目录 → 文件） |
| 文件对象 `web_content_link` | **空字符串** |
| 文件对象 `links` | **空对象** |

结论：**游客能看不能下**，`share/restore`（转存）是唯一路径。

### 9.3 登录后取链

```
POST /drive/v1/share/restore   { share_id, pass_code_token, file_ids:[fid] }
     → params.trace_file_ids = { 老id: 新id }
GET  /drive/v1/files/{新id}?_magic=2021&usage=PLAY
     → links["application/octet-stream"].url
```

### 9.4 CORS 坑（本次最大发现）

从 `pan.xunlei.com` 用 `fetch` 调 `api-pan.xunlei.com`，如果带 `Origin` 或 `X-Client-Version`：

```
Access to fetch at 'https://api-pan.xunlei.com/drive/v1/share?...'
from origin 'https://pan.xunlei.com' has been blocked by CORS policy
```

服务端的 `Access-Control-Allow-Headers` 只放行三个头：

```
x-captcha-token, x-device-id, x-client-id
```

`Origin` 浏览器不允许手写（会被忽略或直接判非法），`X-Client-Version` 不在白名单。删掉这两个后返回 200。
