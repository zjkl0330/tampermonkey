# 百度网盘：从「用不了」到 AccessToken 通道

> 记录时间：2026-11-10　适用版本：云析直链 v1.8.0

## 一、问题现象

脚本在百度分享页能列目录，但点下载一律失败：

- 游客态：`GET /rest/2.0/xpan/share` → `{"errno":-6}`
- 登录后仍偶发失败，报错随页面改版漂移
- 直接拿到的 `dlink` 粘到浏览器能下，粘到 IDM / Aria2 就 403

用户的原话是「最麻烦的是百度」，这个判断是对的：十家里只有百度是**协议层就堵死**的。

## 二、排除法：三条看起来能走的路，全是死路

### 1. 读 Cookie 判登录 —— 物理上做不到

```
BDUSS  → HttpOnly  → document.cookie 读不到
                    → GM_cookie.list 也读不到（Chrome 扩展 API 同样受限）
```

所以「用 Cookie 判断登录态」这个思路从根上就是错的。旧版脚本「明明登录了却提示未登录」，就是因为拿 `BDUSS` 做判断。

正确做法是读页面运行时变量：

```js
unsafeWindow.locals.dump().loginstate   // 0 游客 / 1 已登录
unsafeWindow.locals.dump().bdstoken
```

### 2. `locatedownload` 接口 —— 参数是化石

```
GET d.pcs.baidu.com/rest/2.0/pcs/file?method=locatedownload
    &psign=860a071f77c860e8cea06e4e54c518f3
    &devuid=0F1E9FC2E084472DA5A61C4CF4C759AF
```

`psign` / `devuid` / `cuid` 都是写死的常量，从 2019 年的客户端包里抄出来的。服务端早已不认，返回 `errno=2` 或空 `urls`。

### 3. `api/sharedownload` 免转存 —— 只能下小文件

```
POST /api/sharedownload?sign=&timestamp=&bdstoken=&logid=&jsToken=
     encrypt=0&product=share&uk=&primaryid=&fid_list=[fsid]
```

这条能通，但有天花板：文件偏大时 `list` 直接返回**字符串**而不是数组，内容是「此文件过大，需要保存到网盘后于网盘中下载」。而且它重度依赖 `bdstoken`（页面变量），百度前端一改版就崩。

## 三、转折点：业界已经集体转向 AccessToken

查 LinkSwift（`hmjz100/LinkSwift`，38.8k star，2026-11 仍在更新）的更新日志，1.1.1.6 版（2025-07-28）写着：

> 1、废弃 - 百度网盘 BDUSS Cookie 相关代码，转向使用更安全的 AccessToken；
> 2、**废弃 - 百度网盘分享页面下载相关代码**；

一家维护了两年的项目把「分享页直下」整块删掉，说明这条路已经被官方封死，不是参数没调对。

它改用的方案是：**开放平台 OAuth 拿 access_token，再调 xpan 开放接口**。

## 四、官方文档给出的硬约束（不是经验，是白纸黑字）

来源：<https://pan.baidu.com/union/doc/基础网盘服务/下载/>

```
GET DLINK&access_token=xxx HTTP/1.1
Host: d.pcs.baidu.com

header 参数
  User-Agent   string   是   pan.baidu.com   header   请求头部

URL 参数
  access_token string   是   12.a6b7...      URL参数  接口鉴权认证参数
```

原文三条：

1. `access_token` **拼在 URL 查询串上**，不是 Header；
2. `User-Agent` 必须是 `pan.baidu.com`；
3. 错误码语义：`31045` 令牌验证未通过 / `31362` 签名错误 / `31326` **命中防盗链（UA 不对）** / `31360` 链接过期（dlink 8 小时）。

取链接口（<https://pan.baidu.com/union/doc/基础网盘服务/获取文件信息/查询文件信息/>）：

```
GET https://pan.baidu.com/rest/2.0/xpan/multimedia?method=filemetas
    &access_token=xxx&fsids=[123,456]&dlink=1
Header: User-Agent: pan.baidu.com
→ { "errno":0, "list":[ { "fs_id":123, "dlink":"https://d.pcs.baidu.com/file/..." } ] }
```

**这就是「百度用不了」的真正根因**：浏览器点 dlink 时 UA 是 Chrome，超过 50MB 就被判防盗链 403；而 fetch 改不了 UA，只有 `GM_xmlhttpRequest` 能改。

## 五、OAuth 授权流程（实测）

```
GET https://openapi.baidu.com/oauth/2.0/authorize
    ?response_type=token
    &scope=basic,netdisk
    &client_id=<公开 client_id>
    &redirect_uri=oob
    &confirm_login=0
```

实测（2026-11-10，curl + Chromium）：

| 检查项 | 结果 |
| --- | --- |
| 端点可达 | `HTTP/2 200`，`server: BWS` |
| 页面标题 | 「与百度连接」 |
| 应用名 | `OpenList`（说明该 client_id 未被封禁） |
| 未登录时 | 显示登录表单（`#TANGRAM_3__submit`，按钮文案「登录并授权」） |
| 登录后 | 出现授权确认按钮 `button#auth-allow` |
| 授权成功跳转 | `/oauth/2.0/login_success#access_token=...&expires_in=...` |

`client_id` 用的是开源项目公开的那几个（OpenList / Alist / 百度官方 PC 测试端），脚本里做了数组降级：前一个不通就换下一个。

常用的一组（来自 LinkSwift 源码的白名单，均长期可用）：

```
omiOnr2tYnN9vSyDErcVFWpPU2mZA7YO   // OpenList
iYCeC9g08h5vuP9UqvPHKKSVrKFXGa1v   // Alist
L6g70tBRRIXLsY0Z3HwKqlRE           // pcstest_oauth（百度官方 PC 测试端）
```

## 六、脚本实现要点

```
1. 面板点「一键授权百度网盘」
2. @match 覆盖 openapi.baidu.com → 授权页由脚本注入：
   - authorize 页：轮询 button#auth-allow，命中就自动 click
   - login_success 页：从 location.href 抓 access_token → GM_setValue
3. 主页面轮询 GM 存储，拿到令牌即恢复流程
4. GET /rest/2.0/xpan/nas?method=uinfo&access_token=  校验并显示账号名
5. 取链：xpan/multimedia?method=filemetas&dlink=1
6. 下载：{dlink}&access_token=xxx + UA: pan.baidu.com
```

关键代码分支：

```js
// 只有 GM 通道能改 UA，所以百度 dlink 请求强制走 GM
const wantBaiduUA = /^pan\.baidu\.com$/i.test(String((opt.headers || {})['User-Agent'] || ''));
httpRequest({ ..., forceGM: wantBaiduUA });
```

## 七、实测验证记录

沙箱内无百度账号，能验的都验了：

| 项 | 方法 | 结果 |
| --- | --- | --- |
| 授权页结构 | Chromium 渲染 + DOM dump | 登录框状态可识别，`#auth-allow` 选择器与 LinkSwift 一致 |
| 自动点「允许」 | 注入 `button#auth-allow` 后观察 | 2.5s 内被点中，横幅切到「已自动点击允许」 |
| 令牌抓取 | 构造 `login_success#access_token=...` | 抓到并写入存储，无 JS 报错 |
| 面板入口 | 真实百度首页 + 改写 URL | 「一键授权百度网盘」主按钮正常渲染 |
| 多平台回归 | quark / alipan / ctfile 首页注入 | 面板正常挂载，零报错 |

**未验证**（需要真实账号，客观限制）：授权后 `uinfo` 回包、`filemetas` 取到 dlink、`dlink` 实际下载字节数。这三步的协议来自官方文档 + LinkSwift 生产代码，属于「高置信但未亲测」。

## 八、结论

- 百度**没有**免登录方案。游客 `errno=-6` 是官方关闭，纯前端绕不过；第三方解析站靠服务端账号池，脚本做不到也不做。
- 登录之后，**AccessToken 比 Cookie 靠谱得多**：不碰 HttpOnly、不怕页面改版、30 天有效。
- 下载必须带 `UA: pan.baidu.com`，这一条决定了「交给浏览器」和「分片引擎」的取舍。
