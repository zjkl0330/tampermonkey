# 页面联动：登录态误判、目录错位、勾选同步

> 起因：手机上「明明登录了，面板还显示游客」；「页面已经进了文件夹，面板还停在文件夹列表」；以及「想在网盘里勾文件，直接拿到直链」。
> 版本：v1.9.1 及之前；v1.9.2 修复。

---

## 一、登录态为什么判错

旧实现只有一行：

```js
ctx.logged = /(__pus=|__puus=)/.test(await cookieHeader('https://pan.quark.cn'));
```

问题在 `__puus` 是 **HttpOnly**：`document.cookie` 读不到；手机浏览器多数也没有 `GM_cookie`。结果是「Cookie 里永远没有 `__puus` → 永远游客」。

桌面油猴偶尔能读到，所以这个问题在电脑上不明显，手机上是 100% 复现。

### 三个可用信号（实测）

| 接口 | 未登录返回 | 登录后 |
|---|---|---|
| `GET pan.quark.cn/account/info?fr=pc&platform=web` | `{"success":true,"data":{},"code":"OK"}` | `data.nickname` / `data.user_id` / `data.member_type` 有值 |
| `GET drive-pc.quark.cn/1/clouddrive/member?pr=ucpro&fr=pc` | `401`，`{"status":401,"code":31001,"message":"require login [guest]"}` | `200` + `data.member_type` |
| Cookie `__pus` / `__puus` | 读不到 | 桌面油猴可读 |

`account/info` 是同源接口，最轻，还能顺手拿到昵称；`member` 用来兜底。两个都是 GET、无副作用。

注意跨域：从 `pan.quark.cn` 页面 fetch `drive-pc.quark.cn` 是**同站跨子域**，实测 CORS 放行（能读到 status），`credentials: 'include'` 会把 `.quark.cn` 的 Cookie 带上。

### 改法

```js
ctx.logged = /(__pus=|__puus=)/.test(ctx.cookie);
if (!ctx.logged && cfg.probeLogin) ctx.logged = await cfg.probeLogin(ctx);
```

探测和拿 `stoken` 并行（`probe` 先起，`await` 放在后面），不额外增加等待。

## 二、面板为什么停在上一层

原以为「页面进了文件夹，URL 或请求里一定有 `pdir_fid`」，实测**两者都没有**：

| 动作 | URL | 新请求 |
|---|---|---|
| 打开分享页 | `pan.quark.cn/s/<id>#/list/share` | token + detail(pdir_fid=0) |
| 点进文件夹 | 同上，**完全不变** | **没有**（数据首屏已加载） |
| 再进一层 | 同上 | 没有 |

也就是说夸克把整棵分享树的当前层数据一次性塞进了首屏响应，之后靠前端状态切换。DOM 里也没有面包屑可读（手机端只有一个「返回」按钮）。

### 那就拿「页面上看得见什么」当锚点

```js
names = 页面当前显示的文件名集合        // .file-item .item-tit / tr.ant-table-row
if (当前层 items 与 names 有交集) return // 已经在同一层
否则 BFS 逐层往下翻，翻到哪层命中就切过去（最多 12 个目录）
```

命中判定：`交集数量 >= min(2, names.length)`。页面可能有分页/虚拟滚动，所以不能要求完全一致。

切过去之后按页面顺序重排 items，避免「面板顺序和刚看到的对不上」。

代价：最坏 12 次 detail 请求。实际分享树通常 1~2 层，第一次就命中。

用户一旦在面板里手动进出目录（`state.navLock = true`），就不再跟随，避免抢导航。

## 三、页面勾选同步

### DOM 结构（实测，2026-11）

| 端 | 行 | 文件名 | 复选框 |
|---|---|---|---|
| 手机 | `div.file-item` | `.item-tit` | `input.h5-content-check`（在行末尾） |
| 桌面 | `tr.ant-table-row` | 第 2 个 `td` / `[title]` | `input.ant-checkbox-input` |

### 一个反直觉的坑

夸克手机端的复选框，命名和语义是反的：

```
未点击时： class="h5-content-check h5-content-check-on"   checked = true
点击之后： class="h5-content-check h5-content-check-off"  checked = false
```

而页面底部计数是**递减**的（4 → 3）。也就是说：

- `checked = true` / `-on` = **已选中**
- `checked = false` / `-off` = 未选中

第一次看到 `-off` 差点写成「选中的是 off」。靠「点击后页面显示『已选 3 项』」才定住语义。**不要靠 class 名猜状态，去对照页面自己的计数。**

顺带一个现象：**进入文件夹后页面默认全选**（显示「已选 4 项」），所以同步过来就是全选。这是页面的真实状态，不是脚本自作主张。

### 匹配方式

不依赖 fid，直接拿行的文本去匹配面板 items 的文件名：

```js
items.forEach(it => {
  if (picked.rows.some(row => row.textContent.includes(it.name))) hit.add(it.fid);
});
```

比读 React fiber 里的 props 稳（fiber 里只有 `fileName`，fid 在闭包里拿不到），也不受虚拟列表 DOM 顺序影响 —— 顺序不同没关系，名字对得上就行。

### 不抢用户的操作

```js
if (state.pageSelDirty) return;   // 用户刚在面板里手选过，跳过这次同步
```

`pageSelDirty` 在「面板里勾选」时置 true、打开面板时清 false、换目录时清 false。
另外「页面勾选为空」时不会无条件清空面板 —— 只有上一次确实是页面同步来的才跟着清。

## 四、实测

环境：Playwright + Chromium，Pixel 5 视口（412×860，`is_mobile`、`has_touch`），真实分享页 `pan.quark.cn/s/0cdea8552da5`，GM API 用 fetch + localStorage 打桩。

| 用例 | 结果 |
|---|---|
| 未登录打开 | 标签「游客」，副标题「1 个文件夹 · 游客态」 |
| 页面进文件夹 → 开面板 | 面板切到该层：「4 个文件」，面包屑「根目录 / 【消防安全】📿救援绳结系列(1)」 |
| 页面勾 2 个（第 1、第 3 个） → 开面板 | 面板选中同样 2 个，「已选 2」 |
| 页面勾 1 个 → 开面板 → 面板里改选 → 等 4s | 保持手动选择，未被覆盖 |
| 打桩 `account/info` 返回昵称 | 标签显示「指尖可乐」，副标题去掉「游客态」 |
| 游客态点「复制已选」 | 剪贴板写入失败说明：「游客链有大小限制，请在本站登录后重试」 |
| quark / alipan / 123 / ctfile 回归 | 面板正常挂载，零报错 |

## 五、没验到的

- **登录态下的真实取链**：沙箱里没有夸克账号，`file/download` 的登录分支只有协议、没有回包。游客分支已验证（超过 50MB 被拒，提示正确）。
- **桌面端勾选同步**：只测了手机端 DOM；桌面走 `tr.ant-table-row` + `[title]` 的兜底分支，逻辑相同但没实测。
- **分享树很深时的翻找成本**：上限 12 个目录，更深的层要用户手动进。

## 六、留给下一次的

真要做「勾选即取链」的极致体验，需要把页面自己的 `detail` 响应接住（含每层的 fid/token），而不是靠文件名反推。可行路径是 `page.route` 式的响应拦截，但油猴脚本改 `unsafeWindow.fetch` 侵入性太强，这次放弃了 —— 现在这套 DOM 推断不碰页面网络，兼容性更好。
