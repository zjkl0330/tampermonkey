# 05 · 运行域收窄与自动更新

> 对应版本：v1.9.0（2026-11-11）
> 相关文件：`js/云析直链.user.js` 头部元信息、`checkUpdate()` / `fetchRemoteVersion()`

## 一、为什么要收窄运行域

v1.8.0 的 `@match` 是「域名级全站匹配」：

```
// @match  https://pan.baidu.com/*
// @match  https://cloud.189.cn/*
// @match  https://www.alipan.com/*
...
```

后果有三个：

1. 登录页、注册页、会员购买页、帮助中心都会 `mountUI()`，右下角一直挂个悬浮球；
2. 去广告 CSS 在非分享页也可能命中站点自己的推广元素，属于越界修改；
3. 权限面看起来大，用户装之前会犹豫。

v1.9.0 改成**路径级匹配**：只留分享页 + 平台根路径（根路径是为了保留「打开网盘首页、粘贴链接解析」的习惯用法）。

## 二、新 match 清单怎么定的

逐平台按 `pick()` 里的正反推：

| 平台 | `pick()` 认的形态 | `@match` |
| --- | --- | --- |
| 夸克 | `pan.quark.cn/s/xxx` | `pan.quark.cn/`、`pan.quark.cn/s/*` |
| UC | `drive.uc.cn/s/xxx` | `drive.uc.cn/s/*` |
| 123 | `/s/xx-xx`、`share.123pan.cn/123pan/*`、`?sk=` | 5 条（见脚本） |
| 115 | `115(?:cdn\|rc)?.com/s/sw*` | 3 条 `/s/*` |
| 天翼 | `cloud.189.cn/t/*`、`/web/share?code=` | 2 条 |
| 移动 | `yun.139.com/shareweb/#/w/i/…`、`caiyun.139.com/m/i?…` | 保留 `/*`（hash 路由 + 多套路径，收窄易误伤） |
| 百度 | `pan.baidu.com/s/1*`、`/share/init?surl=` | `/s/*`、`/share/*`、授权页 `openapi.baidu.com/oauth/*` |
| 迅雷 | `pan.xunlei.com/s/*` | 1 条 |
| 阿里 | `ali(pan\|yundrive).com/s/*` | 2 条 |
| 城通 | `(ctfile.com\|ctfile.net\|545c.com)/(f\|file\|d)/…` | 3 条通配子域 |

统一 `@exclude`：`/passport/*`、`/login*`、`/register*`、`/reg.html*`、`/vip*`、`/pay*`、`/about/*`、`/help*`。

### 用脚本验证，而不是靠眼看

Chrome match pattern 的语义（`*` 在 host 段匹配子域、在 path 段匹配任意字符）没法靠肉眼保证，写了个 30 行的转换器把每条 `@match` 变成正则，再对 26 个真实 URL 断言「该启用 / 不该启用」：

```js
function toRe(p) {
  return new RegExp('^' + p.replace(/[.+?^${}()|[\]\\]/g, '\\$&').replace(/\*/g, '.*') + '$');
}
```

结果：26 条用例全过，`夸克会员页`、`天翼首页`、`百度登录页`、`阿里个人盘` 正确落在「不启用」，十个平台的分享页全部命中。

顺带发现一个既有缺陷：`pick()` 支持 `ctfile.net`，但旧 `@match` 里根本没有这个域——城通 `.net` 分享页脚本从来没跑起来过，这次补上了。

## 三、@connect 从 `*` 收紧

`@connect *` 在下载类脚本里很常见，因为 CDN 域名是接口动态下发的，写死就可能 403。代价是「脚本能连任何域」。

v1.9.0 的取舍：

- 接口域 + 已知 CDN 写成通配清单（`*.baidupcs.com`、`*.ctyunxs.cn`、`*.aliyuncs.com`…共 25 条）；
- GitHub raw / api.github.com 加进去（更新用）；
- **失败要说人话**：`GM_xmlhttpRequest` 的 `onerror` 里读 `r.error`，命中 `connect/refused/permission/CSP` 就抛「域名未授权：…（该 CDN 不在 @connect 列表）」，其余才说「网络错误」。

这样漏域不会变成静默失败，也不会被误判成断网。

## 四、自动更新怎么做

### 4.1 第一层：脚本管理器原生机制

```js
// @updateURL    https://raw.githubusercontent.com/zjkl0330/tampermonkey/main/js/%E4%BA%91%E6%9E%90%E7%9B%B4%E9%93%BE.user.js
// @downloadURL  同上
```

Tampermonkey 默认每 24 小时拉一次 `@updateURL`，比对 `@version`，有新版本就在扩展图标上亮红点；`@downloadURL` 负责真正下载。

注意两点：

- **`@namespace` 不能改**。改了等于换了个脚本身份，已装用户不会走更新流程，而是并排出现两个脚本。所以哪怕仓库换了，`@namespace` 仍保留 `https://github.com/CYQawa/YunX`。
- 中文文件名的 raw 地址要百分号编码。`curl` 实测 `.../js/%E4%BA%91%E6%9E%90%E7%9B%B4%E9%93%BE.user.js` 返回 200 / 161332 字节，与 `jsDelivr` 拿到的内容一致。**不用** jsDelivr 当更新源：它对 `@main` 有 12 小时缓存，刚推的版本可能查不到。

### 4.2 第二层：面板内手动检查

`checkUpdate(manual)`：

```
GET  RAW_URL?t=<ts>      Header: Range: bytes=0-2047
→ 正则 /@version\s+([0-9][0-9.]*)/
→ cmpVersion(远端, APP.version)
→ 有新版本：toast + 设置页显示「版本 v1.9.0 → v2.3.1 可更新」+ 确认后打开安装页
```

`cmpVersion` 按段比较，避免 `1.10.0 < 1.9.0` 的字符串比较坑。

### 4.3 第三层：每日静默检查

boot 时读 `GMStore.get('yx_update')`，距上次超过 24 小时才查一次；没新版不弹任何东西。查到的结果缓存下来，设置面板打开时直接显示，不重复请求。

## 五、三个真实的坑

### 坑 1：跨域 fetch 带 Cookie → CORS 直接失败

第一版用默认 `credentials: 'include'` 拉 raw，浏览器报 `TypeError: Failed to fetch`。

原因：`raw.githubusercontent.com` 返回 `Access-Control-Allow-Origin: *`，而带凭据的跨域请求要求 ACAO 必须是具体源且带 `Access-Control-Allow-Credentials: true`。

实测对照：

| credentials | 结果 |
| --- | --- |
| `include` | 失败（5.8s 后 TypeError） |
| `omit` | 200，2.1s，151067 字符 |

改法：给 `fetchRequest` 加 `opt.credentials` 透传，更新检查传 `'omit'`；其余平台请求保持 `include`（它们需要 Cookie）。

### 坑 2：自定义 `Cache-Control` / `Pragma` 头触发预检

为了绕缓存，一开始往请求里塞了 `Cache-Control: no-cache`、`Pragma: no-cache`。这两个不是 CORS 安全列表头，会触发 `OPTIONS` 预检，而 raw 的 `Access-Control-Allow-Headers` 不包含它们 → 预检失败 → `TypeError`。

改法：只用 `?t=<ts>` 破缓存，不手写这两个头。

### 坑 3：整包 body 在无头 Chromium 里读不完

去掉自定义头、改成 `omit` 之后，`fetch` 已在 300–460ms 拿到 `status 200` 和响应头，但 `await r.text()` 一直不返回，直到 15 秒超时被 `AbortController` 掐掉，面板显示「检查更新失败：请求已取消」。

同样的 `fetch` 参数在页面里手写却 823ms 就读完 151067 字符。差异点没能完全复现，但换个思路绕开更划算——**只要脚本头 2KB 就够解析 `@version`**：

```
GET ...user.js?t=<ts>
Range: bytes=0-2047
→ 206 Partial Content，1869 字节，828ms
```

`Range` 属于 CORS 安全请求头，不触发预检。改完之后无 GM 环境（手机浏览器）也能在 1.5 秒内拿到版本号，`localStorage` 里能看到 `{"t":…,"latest":"1.7.0","has":false}`。

## 七、没验到的

- 真实扩展环境下的 `GM_xmlhttpRequest` 拉 raw（沙箱只能用 fetch 桩模拟，TM 的 XHR 不受页面 CSP 限制，理论上更顺）；
- `@connect` 收紧后各平台**真实 CDN 域**是否全在清单里——城通、夸克、天翼已实测过的路径没问题，其余要等实际下载时验证。
