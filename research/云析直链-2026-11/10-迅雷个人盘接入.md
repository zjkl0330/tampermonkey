# 10 · 迅雷云盘个人盘接入（v1.11.0）

> 起因：用户反馈「迅雷云盘的登录页甚至都没有面板」。核实后是两个问题叠在一起：
> 1. `@match` 只有 `pan.xunlei.com/s/*`，个人盘首页压根没注入；
> 2. `@exclude *://*/login*` 把 `/login/` 也排掉了，而未登录访问 `pan.xunlei.com/` 会 302 到那里。
> 结果就是「装了脚本但什么都看不到」。

## 一、现状核实（2026-11-14）

| 探测 | 结果 |
| --- | --- |
| `GET https://pan.xunlei.com/`（无 Cookie） | `200`，但 Playwright 里最终 URL 是 `/login/` |
| 页面 localStorage | 只有 `oauth_sign_in_<client_id>`、`deviceid`、`xl_fp_rt`，**没有令牌** |
| Cookie | `XLA_CI`、`deviceid`、`xl_fp_rt`，都不足以调用 drive 接口 |
| 登录页正文 | 只有「客户端下载 / 产品中心 / 关于我们」，是个纯登录壳 |

也就是说：未登录时读不到任何盘内数据，这时候能给用户的价值只有「明确告诉他要登录」，而不是静默什么都不显示。

## 二、接口：分享那套可以直接复用

`api-pan.xunlei.com` 同时承载分享与个人盘，鉴权是同一套：

| 用途 | 方法 + 路径 | 关键参数 |
| --- | --- | --- |
| 分享列表 | `GET /drive/v1/share` | `share_id`、`pass_code` |
| 分享子目录 | `GET /drive/v1/share/detail` | `share_id`、`parent_id`、`pass_code_token` |
| **个人盘列表** | `GET /drive/v1/files` | `parent_id`、`page_token`、`limit`、`filters`、`with_audit` |
| **个人盘取链** | `GET /drive/v1/files/{id}` | `_magic=2021`、`usage=PLAY`、`thumbnail_size=SIZE_LARGE` |
| 转存（分享） | `POST /drive/v1/share/restore` | `share_id`、`file_ids` |

请求头：

```
Authorization: Bearer <access_token>
X-Captcha-Token: <captcha_token>
X-Device-Id: 78a70629a2b17d0b4302317ffa94807a
X-Client-Id: Xqp0kJBXWhwaTpB6
```

`X-Captcha-Token` 的获取方式与分享页完全一致：`POST https://xluser-ssl.xunlei.com/v1/shield/captcha/init`，
body 里 `action` 填 `METHOD:path`，`captcha_sign` 是 9 层 md5（client_id + 版本 + host + device_id + ts，再依次拼 9 段盐）。

### 关键验证：action 不是白名单

分享页用的是 `GET:/drive/v1/share`。个人盘要换成 `GET:/drive/v1/files`，一开始担心服务端只放行已知 action。
实测（无账号，仅验签名）：

```
GET:/drive/v1/files  → 200 {"captcha_token":"ck0.3s8D_yGC…"}
GET:/drive/v1/share  → 200 {"captcha_token":"ck0.8yC1uBis…"}
```

两个都签发成功，说明服务端只校验签名，不校验 action 白名单。带上 token 再请求：

```
GET /drive/v1/files?parent_id=&limit=50
→ 401 {"error":"unauthenticated","error_description":"帐号认证失败，请重新登录"}
```

链路成立：签名 OK，只差真实令牌。

### 不带设备号会报什么

```
GET /drive/v1/files?parent_id=&limit=10
→ 400 invalid_argument，"device_id is empty"
```

这也是为什么脚本里 `X-Device-Id` 必须带上——不是可选装饰。

## 三、令牌在哪

网页版登录成功后写 `localStorage['credentials_' + client_id]`：

```json
{ "access_token": "...", "refresh_token": "...", "expires_in": 7200 }
```

脚本里原本就有 `xlAccessToken()`（分享页取链用），遍历 `credentials_` 前缀取 `access_token`，
个人盘直接复用，不另存、不上送。

## 四、CORS：页面内 fetch 可行

```
access-control-allow-origin: https://pan.xunlei.com
access-control-allow-credentials: true
access-control-allow-headers: ...,Authorization,csrf-token,X-Captcha-Token,X-Device-Id,X-Client-Id,...
```

ACAO 是**具体源**而不是 `*`，所以必须从 `pan.xunlei.com` 页面里发起（`credentials: include`），
`preferPageFetch()` 对 xunlei 域本来就返回 true，无需改动。四个自定义头都在 allow-headers 里，预检能过。

## 五、DOM 与交互

| 点 | 处理 |
| --- | --- |
| 页面勾选 → 面板 | 复用 v1.9.2 的行文本匹配（`tr.ant-table-row` / `.file-item`），按文件名对 fid |
| 面板 → 页面 | 面板改选后 `pageSelDirty` 暂停反向同步，避免互相抢 |
| 目录跟随 | hook 页面 `fetch` / `XHR`，抓 `/drive/v1/files` 请求里的 `parent_id`；空串代表回根目录 |
| 去广告 | 个人盘不注入，`[class^="ad-"]` 有误伤风险 |

`parent_id` 与 123 的 `parentFileId` 语义一致，所以 `hookMineDir()` 只是多加一个正则分支，没有另起一套。

## 六、实测（Playwright 打桩，无真实账号）

伪造 `pan.xunlei.com` 页面 + 拦截 `api-pan` / `xluser-ssl` 返回真实结构：

| 场景 | 结果 |
| --- | --- |
| 已登录 + 根目录 | 标题「我的迅雷云盘」，副标题「1 个文件，1 个文件夹」，标签「已登录」 |
| 勾选一个文件 → 复制 | 真实鼠标点复选框 → `.row.sel` 命中 → 剪贴板得到 `https://dl.xunlei.example/f/222?sig=abc` |
| 下钻文件夹 | 面包屑「我的云盘/相册」，列表换成子目录内容 |
| 跟随页面目录 | 页面发 `parent_id=111` → 面板自动切到「相册」，行变成子目录文件 |
| 未登录 | 「读不到登录令牌：请先在 pan.xunlei.com 登录…」，标签「游客」 |
| 令牌过期（401 unauthenticated） | 「迅雷登录态已失效…」，标签「登录失效」 |
| 123 回归 | 昵称、勾选、取链、分享页全部照旧 |

## 七、仍未验证 / 已知限制

- **真实令牌下的回包**：字段名按 `drive#folder` / `files` / `next_page_token` / `web_content_link` 写，
  与分享接口同构，但没有账号无法确认分页真实形态（`next_page_token` 为空串时视为末页）。
- **直链防盗链**：`web_content_link` 通常校验 UA / Referer，脚本的浏览器直下可能 403；
  复制直链给 IDM / aria2 时记得带 `Referer: https://pan.xunlei.com/`。
- **登录页注入**：为了「未登录也能看到球」，把 `*://*/login*` 从 `@exclude` 拿掉了。
  挡输入框的风险由 v1.9.1 的「检测可见密码 / 验证码框 → `.away`」兜底，但其他站点登录页也一并放开了，需要观察。
