# 悬浮球：为什么会出现两个，为什么会挡住验证码

> 现象来源：手机端夸克分享页，页面右侧同时出现两个蓝色 ⚡ 球，其中一个压在「请输入验证码」输入框上，点验证码框点不到。
> 版本：v1.9.0 之前；v1.9.1 修复。

---

## 一、两个球是怎么来的

代码里 `mountUI()` 只渲染一个 `.fab`，模板里 `ICON.bolt` 全脚本只出现一次。所以两个球不可能来自同一份脚本的同一次注入，只剩三种可能：

| 可能 | 机制 | 能不能脚本自己修 |
|---|---|---|
| 同一页面被注入两次 | 浏览器自带脚本引擎（夸克 / X 浏览器）+ 油猴扩展各跑一份，两份各自 `mountUI()`，`host` 的 id 相同但都是独立节点 | 能，加互斥 + 清场 |
| 旧版本没被覆盖 | 更新脚本时旧版还在（不同 `@name` 或手动复制过），旧版也有一份 `mountUI()` | 能，清掉非自己的 host |
| 装了另一款直链脚本 | 别人的 host id 不同，图标也常用 ⚡ | 不能，只能让用户删 |

关键点：**脚本内 `state.mounted` 只能挡住自己这一份**。两份脚本是两个独立闭包，各自的 `state` 互不可见，所以守卫形同虚设。

### 修法

```js
// ① window 级互斥：第二份脚本进来直接退出
if (window.__YX_UI__) return;
window.__YX_UI__ = 1;

// ② 清掉页面上已经存在的 host（旧版残留、别的注入）
document.querySelectorAll('#yunx-panlink-host').forEach(el => el.remove());

// ③ 自己的 host 记在 state.host，每 2 秒巡检一次，多出来的（不是自己的）移除
setInterval(() => {
  const list = document.querySelectorAll('#yunx-panlink-host');
  if (list.length <= 1) return;
  list.forEach(el => { if (el !== state.host) el.remove(); });
}, 2000);
```

③ 是必要的：如果旧版脚本在新版之后执行，它还会建一个球，只能事后清。

顺带修了一个隐患：`getRoot()` 原来用 `document.getElementById('yunx-panlink-host')`，页面上有两个 host 时会拿到别人的，导致面板操作错对象。现在优先返回 `state.host`。

## 二、为什么挡住验证码

原来的球是 `position: fixed; right: 22px; bottom: 96px; width: 54px`。手机竖屏下这个位置正好落在**底部登录弹层的验证码输入框右侧**——夸克的登录弹层是全宽底部抽屉，输入框右边还叠着「获取验证码」文字按钮，球的 54px 宽度直接盖住了它。

`z-index: 2147483000` 又比页面弹层高，所以是真盖住，不是视觉重叠。

### 修法：拖动 + 自动让位

**拖动**：`pointerdown/move/up` + `setPointerCapture`，超过 7px 才判定为拖动（否则仍是点击）。松手后按球心落在屏幕哪一半吸附到左/右边缘，垂直位置存成**比例**（`0.10 ~ 0.82`）而不是像素——换设备、转屏都能落回合理位置。

```js
GMStore.set('yx_fab_pos', { side: 'left', ratio: 0.764 });
```

拖动结束后浏览器会补一个 `click`，必须在 capture 阶段掐掉，否则一拖就弹面板：

```js
fab.addEventListener('click', (e) => {
  if (!fabDragged) return;
  fabDragged = false;
  e.stopImmediatePropagation();
  e.preventDefault();
}, true);
```

**自动让位**：每 1.2 秒扫一遍可见的密码框 / 验证码框：

```js
input[type=password]
input[placeholder*="验证码"] / "密码" / "口令"
input[name*=captcha] / [class*=captcha] input / [class*=pass-form] input
```

命中且元素在视口内、尺寸正常、不是 `display:none/visibility:hidden/opacity<0.15`，就给球加 `.away`：

```css
.fab.away { opacity: 0; pointer-events: none; transform: scale(.6) translateX(28px); }
```

`pointer-events: none` 是关键——只淡出不做这一步，透明球仍然吃掉点击。

## 三、实测

环境：Playwright + Chromium，Pixel 5 视口（412×860，`is_mobile`，`has_touch`），stub 掉 GM API。

| 用例 | 结果 |
|---|---|
| 同一脚本连续注入两次 | `#yunx-panlink-host` = **1**，shadow 内 `.fab` = 1 |
| 预先塞一个「旧版残留」host 再加载 | 加载后 host = **1**（残留被清） |
| 再手动塞一个 host，等 2.6s | host = **1**（巡检清掉） |
| 点球（未拖动） | 面板正常打开 |
| 注入模拟登录层（验证码 input） | 球 `class="fab away"`，`opacity: 0`，`pointer-events: none` |
| 移除登录层后 1.8s | 球恢复 `class="fab"`，`opacity: 1` |
| 拖动到左侧 → 松手 | 存 `{side:"left", ratio:0.764}`，球吸附到 `x=14` |
| 拖动后 | 未误触发面板打开 |
| 桌面 1100×800 | 球在右侧中部，不压正文 |
| quark / alipan / 123 / ctfile 回归 | 面板正常挂载，零脚本报错 |

## 四、遗留

- 若是**别人家的脚本**也画了一个球（host id 不同），本脚本无法识别也无法删，只能让用户在脚本管理器里关掉那一份。
- 拖动位置按视口比例存，手机横屏时球可能落在键盘区域上方；键盘弹出后视口高度变化会触发 `resize`，会重新贴边，但极端比例（ratio < 0.1）已夹到 0.10 下限。
