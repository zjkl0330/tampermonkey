# 09 · 123 个人网盘接入（2026-11-14）

## 起因

用户反馈两件事：123 云盘不能在网盘里勾选文件直接下；面板根本读不到自己盘里的文件，因为脚本只认分享页。
此前 v1.9.0 收窄运行域时，`yun.123pan.cn/*` 虽然在 `@match` 里，但 `pick()` 只匹配 `/s/<key>`，没有 shareKey 就返回 null，等于只在分享页有效。

## 先把「个人盘长什么样」查清楚

| 事实 | 证据 |
| --- | --- |
| 个人盘在 `https://yun.123pan.cn/`，未登录会 302 到 `https://user.123pan.cn/centerlogin?redirect_url=...` | Playwright 打开发现在即跳转，`location.href` 就是这条 |
| `www.123pan.com` / `www.123pan.cn` 首页是**营销页**（93KB / 101KB），`/home` 返回 404 | curl 探路；真正的盘是 3.6KB 的 SPA 外壳 |
| `yun.123pan.cn`、`yun.123pan.com`、`www.123865.com`、`www.123684.com` 任意路径都返回同一个 SPA 外壳（3662B） | SPA fallback，路径由前端路由决定 |
| 接口在 `https://yun.123pan.cn/api/...`，与页面同源 | 无令牌请求返回 `{"code":20101,"message":"未登录"}`，证明路由存在、鉴权在业务层 |

接口字段不是猜的，对齐 OpenList 的 123 驱动（`drivers/123/util.go` + `driver.go`）：

```
GET  /api/file/list/new
     driveId=0&limit=100&next=0&orderBy=file_id&orderDirection=desc
     &parentFileId=<id>&trashed=false&SearchData=&Page=<n>
     &OnlyLookAbnormalFile=0&event=homeListFile&operateType=4&inDirectSpace=false
POST /api/file/download_info
     {driveId:0, etag, fileId, fileName, s3keyFlag, size, type}
headers: authorization: Bearer <token>, platform: web, app-version: 3,
         origin/referer: https://yun.123pan.cn
```

响应 `data.InfoList[]` 里 `FileId / FileName / Size / Type(1=目录) / Etag / S3KeyFlag` 正是取链要的四个参数；
`data.Next == "-1"` 为末页。

下载这一步比分享页多一层：`data.DownloadUrl` 是带 `params=<base64>` 的中转地址，base64 解开才是真正的入口，
再跟一次会 302 到 CDN（或返回 `data.redirect_url`）。所以实现了 `resolveMineUrl`：优先 `finalUrl`，其次 JSON 里的
`redirect_url`，两者都失败就把解出来的中转地址原样交出去——IDM / aria2 自己能跟 302。

## 凭据从哪来

前端包里取令牌的写法是 `p = HH() || i.l.load("accessToken")`，也就是 **localStorage 的 `accessToken`**。
实测未登录时 `localStorage` 只有 `_l_KPiPs` 和 `LoginUuid`，cookie 里也没有鉴权项（只有统计用的 `_pk_*`、`aliyungf_tc`），
所以令牌确实只在 `accessToken`。脚本读这个键，找不到再退到 `authorToken / token / userin.token`。

## 目录跟随：别用文件名反推

夸克那套「拿页面上显示的文件名逐层下翻」对 123 无效（DOM 结构完全不同，`pageVisibleNames` 抓不到）。
改成一个更硬的信号：**页面自己每次列目录都会带 `parentFileId`**，hook 住 `fetch` / `XMLHttpRequest.open` 记下这个值，
面板直接按这个 id 去列——不用猜层级，一次请求到位。用户手动在面板里导航过（`navLock`）就不抢。

## 页面勾选怎么认

123 用的是 antd 的复选框，但行是自绘 div，类名是 CSS Modules 哈希（选中态是 `.rowSelected_yqItm`），
既没有 `tr.ant-table-row` 也没有 `.file-item`。做法：

1. 先找 `input[type=checkbox]:checked`（antd 的原生 input 会保留 checked）；
2. 往上最多 8 层找第一个「带文件名单元格」的祖先当行（`[class*="file-name"]`、`[class*="table-file"]` 等，类名证据来自 `app.c62a49....css` 里的 `.table-file-name` / `.table-list-file-name`）；
3. 再按行文本和 API 列表的文件名做包含匹配得到 fid。

## 验证（没有账号，只能打桩到协议层）

Playwright 里伪造 `yun.123pan.cn` 页面 + 拦截 `/api/*` 返回按 OpenList 结构造的数据：

| 用例 | 结果 |
| --- | --- |
| 挂载与登录态 | 标题显示 `测试号`（取 `user/info` 昵称），副标题 `123 云盘 · 1 个文件，1 个文件夹` |
| 页面勾选 → 球徽标 | 合成 123 风格 DOM（`.table-file-name` + antd 复选框），徽标显示 `1`，面板打开后该行已选中 |
| 面板内取链 | `download_info` → `params` 解码 → 跟 302 / JSON `redirect_url`，剪贴板拿到 `https://cdn.../f1?sig=final` |
| 目录下钻 | 点文件夹行 `.nm` → 第二次请求 `parentFileId=2`，面包屑 `我的云盘/相册`，内容随之替换 |
| 跟随页面目录 | 页面自己发 `parentFileId=2` 的请求后面板自动切到该目录，面包屑 `我的云盘/页面所在目录` |
| 登录失效 | `user/info` 返回 20101 → 面板写「登录态无效或已过期：请在 yun.123pan.cn 重新登录」 |
| 分享页回归 | 123 分享页仍正常列出文件、标题取 `ShareName`，未受影响 |

## 未验证 / 已知限制

- **真实账号没跑过**：令牌、`download_info` 的真实回包、当日流量限制都只能在登录后验证。菜单里加了「🔍 诊断 123 个人盘」，
  会依次打印令牌长度、`user/info` code、根目录前几项、首个文件取链结果，出错直接复制这段。
- 页面勾选依赖 antd 复选框的 `checked` 状态；如果 123 改成 svg 勾选或受控组件不保留 input，需要再适配。
- 只有 123 做了个人盘；夸克 / UC 是另一套（`__puus` + `/1/clouddrive/file/download`），未接。
- `mineList` 每页 100 条、最多 50 页，超大目录会慢；没有并发，避免踩 123 的频率限制。
